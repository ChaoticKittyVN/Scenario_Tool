# 音频资料 audio_data

音频资料表位于 `param_config/audio_data.xlsx`，和 `param_data` 放在同一目录。只包含 `Music`、`Ambience`、`Sound` 三张普通工作表，没有说明页、样式、批注、冻结或筛选设置。

## 表格列

前两列仍使用现有映射约定 `ExcelParam`、`ScenarioParam`，后面是六个中文维度，共八列：

| 列名 | 填写内容 |
| --- | --- |
| ExcelParam | 必填：演出表中的参数名。 |
| ScenarioParam | 必填：当前项目及引擎的实际调用值。 |
| 情绪色彩 | 音乐本身传达的感受，可混合、可随播放变化。 |
| 张力与能量 | 在一格内分别描述张力和能量，如“低张力；高能量”，不合并成强度或音量。 |
| 节奏与运动感 | 音乐怎样流动、推动或停驻。 |
| 音色与风格 | 音色、质感、配器和风格。 |
| 发展与结构 | 开头、主体、中段变化和收束；可以写文字，不要求时间轴。 |
| 叙事用途 | 本项目推荐或已确认的叙事作用、适用条件及必要限制，可有多种用途；不填写章节、行号和台词组成的使用位置清单。 |

六个维度都是可选自由文本，不要求唯一标签或固定词表。环境音和音效可以只填两列映射。普通填写任务保留映射列，只增加或填写这六列；必要限制、关联和来源可简短注明，已确认用例只提炼有依据的用途结论，不将位置清单或核查过程作为维度内容。工具能保留并导出自定义列，但这项兼容能力不代表当前任务要求新增列；用户明确要求或项目已确认采用的扩展结构按其执行，也不因默认模板自动删除既有扩展列。

资料来自试听、用户确认、素材说明还是待核实推断，应在对应描述或附加资料中注明。未知内容留空，不自动填成 false、0 或引擎默认值；“有循环感”不证明文件可以无缝循环。工具不推断听感，也不按情绪自动选曲。

曲目描述和项目用法放在本表。本次段落选什么、在哪里开始或停止，继续记录在演出方案或生产表里，不在音频资料中重复登记。

“叙事用途”描述音乐适合承担的作用，例如关系缓和、悬念维持或冲突后的情绪回落；章节、Index 和台词仅说明现在哪里使用，不能替代用途判断。前五个维度须有音频本身的相应依据，不根据剧情或曲名倒推听感；频谱、RMS 等原始统计也不能代替音色或结构结论。无法支持的描述可以留空，不要求填满六列。详细判断边界由 `chaotic-vn-performance-director/references/music-data.md` 维护。

## 配置与文件选择

```yaml
audio_data:
  enabled: false
audio_doc_export:
  enabled: false
  output_file: audio_doc.json
```

填好资料后，将 `audio_data.enabled` 改为 `true`。`audio_doc_export.enabled` 控制完整更新和仅映射模式是否附带导出 JSON；关闭自动导出时，也可单独执行导出命令。

文件均从 `paths.param_config_dir` 读取，默认是 `param_config`：

| 范围 | 专用资料 | 通用资料 |
| --- | --- | --- |
| 无项目配置 | 无 | `audio_data.xlsx` |
| 单项目 | 优先使用 `audio_data_<项目键>.xlsx` | 没有专用文件时使用 `audio_data.xlsx` |
| 多项目 | 按 `projects` 顺序加载存在的 `audio_data_<项目键>.xlsx` | `audio_data.xlsx` 作为共享基础 |

项目键来自 `projects`，音频文件名不包含引擎层。旧的 `audio_data_<engine>.xlsx`、`audio_data_<engine>_<project>.xlsx` 不作为引擎专用来源读取；只有后缀本身是实际项目键时才是合法项目文件。

选择与合并沿用普通参数的现有语义：单项目专用文件整份优先，不再合并未选中的通用文件；多项目使用通用基础加项目资料，同类型、同 `ExcelParam` 的整条记录由项目资料覆盖，不拼接两份描述。调用同一映射合并函数；候选沿用有序去重合并。缺少某项目专用文件时仍可使用通用资料，不会读取其他项目的专用资料。

多项目仍需开启 `multi_project_mode`。演出表未匹配项目时使用通用候选；匹配多个项目时沿用普通参数的警告并取第一个行为。

旧项目不启用 `audio_data`，仍按原路径使用 `param_data`。没有专用文件可按规则选择通用文件；一旦选中的文件损坏、缺列或无效，命令失败，不通过换源掩盖错误。单项目未选中的通用文件不影响专用来源；多项目存在的通用文件和各项目专用文件都是选中来源，均须有效。既没有专用文件也没有通用文件时失败。只有表头的音频工作表可以表示该类型暂时没有候选。

## 映射与冲突

- 音频源中存在的工作表接管该类型，空工作表也接管；不接管的类型删除对应工作表，继续从 `param_data` 读取。
- 已接管类型不得在实际使用的 `param_data` 中保留非空数据，即使映射完全相同也报错。多项目配置在基础和各项目参数文件中检查。
- 同类型重复 `ExcelParam` 报错；不同名称可以映射到同一 `ScenarioParam`。
- 通用与项目专用同名记录按上述普通参数规则覆盖；不同项目的同名映射也沿用普通参数的顺序覆盖，不增加音频专用的跨项目禁用规则。
- 映射缺值、重复列名、无标题数据或 Excel 错误值会报错，完全空白行忽略。公式与普通参数一样读取 Excel 保存的缓存值；必填映射没有缓存值时按缺值报错。非音频工作表不参与读取，可保留项目自己的说明或词表。

音频映射仍写入统一的 `param_mappings.py`，生成器和资源校验使用现有消费链。维度不参与生成资源 ID，不改变引擎播放参数。

普通参数最终使用一个全局映射。例如项目 a 的 `Music/共享曲 → first` 被后加载的项目 b 的同名映射 `→ second` 覆盖后，两个项目的该名称都会调用 `second`。音频候选仍按各项目筛选；JSON 对被覆盖的调用采用实际胜出的整条记录并保留来源，日志说明覆盖关系，不把旧资源描述拼到新调用值上。调用值相同时，各项目自己的描述和用途仍分别保留。未匹配项目的演出表使用通用候选，也遵守同一全局调用规则。

## 更新与导出

在仓库根目录运行，可追加 `--config <配置路径>`、`--engine renpy` 或 `--engine naninovel`：

```powershell
# 只验证并预览
python update_param.py --dry-run

# 生成统一映射；按配置附带导出文档
python update_param.py --mappings-only

# 只同步指定演出表的参数候选
python update_param.py --parameter-sheet-only --workbook "<演出表.xlsx>"

# 只导出音频资料
python update_param.py --audio-doc-only
```

直接执行 `python update_param.py` 会生成映射并同步 `input_dir` 中的参数表，按配置附带导出资料。映射变动后同时更新映射与候选；只改描述时，只导出音频文档即可。

默认文档是 `param_config/audio_doc.json`。`default` 保存实际采用的通用资料，`projects[项目键]` 保存该项目的有效资料；单项目专用整份优先，多项目专用覆盖通用同名记录。每个范围的 `source_files` 列出有效来源，记录的 `source_file` 与 `source_row` 标明整条记录来自哪里。按 `types[类型].records[ExcelParam]` 查询完整记录，六个中文维度和附加列原样保留在 `attributes` 中；按调用值查询使用同范围的 `scenario_index[ScenarioParam]`。不附加核实状态或依据协议；来源与未知按原有描述保留，已有自定义列也按普通资料导出。输出由源表生成，不另行手工维护，内容相同不重复保存。

普通任务中的“导出音频专用文档”沿用此 JSON 出口，不默认增加 Markdown、HTML 手册、播放器或渲染脚本；其他展示形式仅在用户要求或既有项目契约规定时制作。

新建资料表时复制仓库提供的 `param_config/audio_data.xlsx`，按文件选择规则命名后填写。
